## 问题与范围

本机与Pages存储origin隔离；保留访客模式，账号云端恢复。同一版本保留三语、136神庙/15塔、小图标、无聚合、阈值切换、不剧透及DLC隐藏不删记录。

- R1：Supabase未配置时正常访客模式，云端入口清楚说明未配置，不模拟成功。
- R2（r2）：邮箱注册与密码登录/GitHub OAuth、会话恢复/退出；注册/凭据/会话错误、OAuth失败、Pages子路径回调。暂停邮箱验证码与邮件服务，不提供邮件找回密码。
- R3：云记录按认证user_id+game_id+shrine_id隔离；数据库RLS强制约束，A不可读写B，管理密钥不入前端。
- R4：登录读取云记录，逐座同步完成与取消；缓存/持久待同步队列按UID隔离，离线重启可重试，切账号不会串写或清空。
- R5：服务器版本检查处理同座冲突，预览并明确解决；不能简单并集使取消完成复活。
- R6：v1访客进度、JSON导入导出保留；首次登录迁移预览数量、明确合并/替换并备份，原数据保留。跨origin仍需导出导入。
- R7：访客/账户身份可见；真实状态包括本机已保存、同步中、云端已同步、离线待同步、失败、冲突。存储异常不假报成功。
- R8：三语、详情/设置、DLC、Pages路径及原地图受影响回归。

授权开发、独立测试和Supabase接入准备。尚无项目配置、OAuth App和正式SMTP，真实云RLS、邮件、OAuth及跨设备同步须在实际项目验证；不得将模拟测试写成云联调成功。缺配置不妨碍实现和准备候选。不得创建付费资源、读取其他项目密钥或公开用户进度。独立分支本机验收后再处理生产发布，不把未验收版本推到main。未授权删除数据或绕过保护。

## r2 本人需求变更（2026-10-11，Asia/Taipei）

用户原话：「先不上线邮箱服务吧。直接用户自己输入邮箱和密码即可使用。」

沿用同一v0.2.0，r2替代R2的OTP流程为邮箱注册/密码登录；GitHub、访客及R1/R3—R8不变。密码只在提交认证时发送Supabase Auth，不进环境变量、队列、备份、临时视图、日志或公开资料。本机数据库密码不是任何网页用户的登录密码。

直接注册可用需要Supabase邮箱确认关闭；该开关尚未调整，代码将先支持真实session与“确认尚未完成”的异常分支，不能signup返回user就宣称登录。此模式邮箱仅是登录标识，不证明邮箱归属；无邮件服务时不提供自助找回密码。浏览器操作规则对关闭确认保护要求当场确认，主代理完成可审查代码/表单后再请本人确认。

r1设计、实现快照、测试报告与证据保留在revisions/r1及原evidence，不代表r2已验证。当前r2尚未实现/测试/验收/发布。
