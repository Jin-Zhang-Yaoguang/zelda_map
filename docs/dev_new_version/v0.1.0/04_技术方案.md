依据01需求、02PRD、product_handoff、AGENTS.md及03UIUX。共同及技术角色记忆为空；初始目录无应用代码、Git提交或依赖锁文件，不虚构基线提交。

## 2. 公用数据合同

生产文件`public/data/shrines.json`，类型`src/types.ts`，JSON Schema为`data/schema/shrines.schema.json`，均由数据worker实现。精确字段如下：

```ts
type Locale = 'zh' | 'en' | 'ja';
type LocalizedText = Record<Locale, string>;
type ShrineId = `Dungeon${string}`; // 运行时限Dungeon000..135
type VerificationStatus = 'verified' | 'unverified' | 'conflict';
interface SourceRef {
  id: string; title: string; url: string; retrievedAt: string;
  hash?: string; locator?: string;
}
interface FieldEvidence {
  status: VerificationStatus; sourceIds: string[]; note?: string;
  displayNote?: LocalizedText;
}
interface Region { id: string; name: LocalizedText }
type TowerId = `Tower${string}`; // 运行时限Tower01..Tower15
interface TowerRecord {
  id: TowerId;
  name: LocalizedText;
  position: { x: number; y: number; z: number };
  regionId: string;
  sourceId: string;
  verification: Record<'name' | 'position' | 'region', FieldEvidence>;
}
interface ShrineRecord {
  id: ShrineId;
  sourceId: string;
  name: LocalizedText;
  trial: LocalizedText;
  regionId: string;
  dlc: boolean;
  position: { x: number; y: number; z: number };
  safe: { summary: LocalizedText; prerequisite: LocalizedText };
  detail: {
    intro: LocalizedText;
    prerequisites: LocalizedText[];
    supplies: LocalizedText[];
    walkthrough: LocalizedText[];
  };
  verification: Record<
    'name' | 'position' | 'region' | 'safe' | 'intro' |
    'prerequisites' | 'supplies' | 'walkthrough', FieldEvidence
  >;
}
interface ShrineDataset {
  schemaVersion: 1;
  dataVersion: string; // 初版v0.1.0-20261011，数据变更更新
  game: 'botw';
  generatedAt: string;
  regions: Region[];
  sources: SourceRef[];
  shrines: ShrineRecord[];
  towers: TowerRecord[]; // r2新增15座定位塔，不进入神庙进度
}
```

`sourceId`本版为 `wiki-DungeonXXX` 并引用根级 sources；稳定 `id` 保留原始游戏 Dungeon ID。姓名/试炼直接映射游戏文本label，`position.X/Y/Z`转为小写并保留精度。`regionId`引用根级regions；`sourceIds`引用根级sources，verified须有对应事实来源。来源保留URL、采集日期、章节/字段、可用原文sha256。

所有三语值非空；正文是本站原创整理/译述，不复制整页指南。缺口使用明确三语状态并记unverified，不能凭非空字符串算完整。空数组仅用于来源确认无额外依赖/物资；待核实与没有分开。官方名称逐ID核对来源；自译不得标官方译名。

safe与detail独立撰写，禁止全文截断生成安全摘要。外层组件只接收`id/name/regionId/dlc/position/safe`及完成状态；trial仅详情显示。搜索只索引三语名称和地区，Unicode规范化后匹配，不检索攻略/物资/详细前置。

资料均按纯文本渲染。禁止`innerHTML`、`dangerouslySetInnerHTML`与动态字符串`bindPopup`；Leaflet动态文本用安全DOM/textContent。外链只许http/https，使用noopener noreferrer，标可能剧透。Schema拒绝结构外字段；浏览器数据加载另做必需字段、ID与引用校验。

## 3. 底图与投影

Leaflet CRS.Simple配本地ImageOverlay；不是地理经纬度。唯一换算：

```text
游戏平面x∈[-6000,6000]、z∈[-5000,5000]；图片3000×2500
u=(x+6000)/4；v=(z+5000)/4
Leaflet [lat,lng]=[-v,u]
bounds=[[-2500,0],[0,3000]]
逆变换x=4*lng-6000；z=-4*lat-5000
```

y仅高度，不参与平面点位。不重复保存像素坐标，前端及数据检查共用公式。初始fitBounds，负minZoom允许缩小，小屏面板变更后invalidateSize；复位只重置视角。点位按稳定ID连接列表与详情。r2禁止聚合及重定位，密集点仍在原坐标单独显示，通过更高缩放或列表选择。

地区以MapTower多边形点内计算，先核对轴/编号；未归属、边界或多归属输出异常并校对，不静默最近高塔补齐。范围检查不代替地区/地标/DLC人工对照。底图失败仍可列表浏览并重试。

锁Leaflet1.9.4稳定API；官网主API已指向2.0 alpha，不照抄新版构造器。CRS原理依据[Leaflet官方示例](https://leafletjs.com/examples/crs-simple/)。

## 4. 状态与交互接口

App/store唯一状态入口，组件派发动作。Settings为`{schemaVersion:1,locale,showDlc}`；MapContext包含`center:[number,number],zoom,query,regionId:null|string,completionFilter:'all'|'completed'|'incomplete',selectedId:null|ShrineId`。完成集合为`Set<ShrineId>`，保存时排序唯一数组。

动作：`selectShrine(id)`、`setCompleted(id,boolean)`、`setLocale`、`setShowDlc`、`setFilters`、`resetMapView`、`exportProgress`、`previewImport`、`restoreImport`。完成写显式目标值，不接受未知ID；重复动作不重复计数。

先按DLC得到120/136范围，再应用搜索/地区/完成筛选。范围进度和结果计数分别算。DLC隐藏不删除完成集合，导出含隐藏ID；当前DLC预览清除，已开详情保留且提示隐藏。语言切换保留全部上下文及当前详情展开区；进入/退出详情或换ID后敏感区重新折叠。

MapContext在App层保存，详情/设置返回恢复中心、缩放、筛选、选择；返回前重新校验选择是否仍可见。列表与地图双向选择，键盘列表提供等效操作。移动端面板开合不重载数据或清空筛选。

加载区分loading/ready/error，数据失败不显示0座；存储区分ready/unavailable/corrupt，失败三语提示及恢复入口。03已落盘并与上述hash、状态、DLC、折叠及safe合同对齐。

## 5. 存储与备份

键名固定：`zelda-map:botw:v1:progress`、`zelda-map:botw:v1:settings`、`zelda-map:botw:v1:pre-import`。progress为`{schemaVersion:1,game:'botw',dataVersion,completedIds,updatedAt}`；settings为上节对象。数据版本更新不换进度键。

读取/解析/验证/写入均捕获异常。读取完成前不自动保存默认值；损坏数据不写空集合覆盖原记录，保留原字符串，允许本次会话操作和导出并提示未保存。恢复损坏存储须明确操作且先备份原记录。写失败保留会话状态，禁止显示成功。设置和进度独立失败互不覆盖。

固定`http://127.0.0.1:5173`及strictPort，占用直接报错，不能自动换地址导致新存储。开发与构建预览不同时运行；地址/端口变更前导出迁移。来源隔离及失败依据[MDN localStorage说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。

导出格式固定`{format:'zelda-map-progress',schemaVersion:1,game:'botw',dataVersion,exportedAt,completedIds}`，全部完成ID含隐藏DLC，以JSON Blob下载，不包含攻略。导入只改进度，限1MiB；解析后复制白名单字段，不把对象合并进应用对象。

导入验证格式/游戏/schema、日期、类型、数组/ID与已知集合；重复去重并说明。不同dataVersion在同schema下可提示后继续；未知ID整体拒绝并显示具体ID，取消/失败原集合不变。校验成功先预览当前数→恢复数，用户点击恢复才替换。

替换前保存pre-import并读回；失败先提供原进度下载，再允许会话恢复并提示未持久保存。正常路径新进度写入/读回成功后再提交状态及成功提示，失败保留原有效集合。不能借导入悄然改语言/DLC。
