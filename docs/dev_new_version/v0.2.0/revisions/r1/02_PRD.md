# v0.2.0 PRD

日期：2026-10-11。角色：product_manager。需求基线：`01_需求文档.md`；代码基线：2686aa1，分支 dev/v0.2.0。

本文是设计与验收口径，尚无本人验收或真实 Supabase 联调结论。用户明确支持邮箱验证码与 GitHub 两种登录方式。

## 1. 目标、证据与边界

个人玩家在本机或 Pages 标记神庙后，需要在同一账号的其他设备恢复进度，同时继续允许不登录使用。现有浏览器存储按 origin 隔离，切设备或从本机转 Pages 不会自动带走数据。

已核查当前行为：`src/lib/progress.ts` 的 `STORAGE` 使用 v1 访客存储；`readProgress` 读取 completedIds；JSON 备份为 schemaVersion 1、game=botw；`src/App.tsx` 的导入预览及替换先保留旧进度。语言、DLC 为浏览器偏好。完成与取消完成目前均写本地；现有成功 toast 不区分保存失败，是本版 R7 需要修正的路径。

需求来源：R1—R8 均来自 `01_需求文档.md`。身份分区、加载屏障、冲突说明和备份恢复细节是满足上述需求的产品约束，由技术与 UIUX 选择具体实现，不是新增用户功能。

本版包含账号认证、逐座云同步、v1 本地迁移、保存状态与必要异常处理。继续保持三语、136 神庙、15 塔、地图小图标、无聚合、缩放阈值切换、不剧透和 DLC 隐藏不删记录。

不增加排行榜、公开进度、社交关系、塔完成计数、游戏内容修订或跨游戏扩展。云同步只包含神庙完成记录；语言与 DLC 显示偏好维持设备本地。本版交付为本机候选，v0.1.0 线上继续运行。

## 2. 身份与数据口径

| 概念 | 产品口径 |
| --- | --- |
| 访客 | 当前浏览器 origin 的 v1 本地进度，无云端身份；可标记、取消、导入、导出 |
| 账号 | 认证 user_id 所属的 botw 神庙进度；界面显示可识别的账号信息及云状态 |
| 完成记录 | stable shrine_id 对应完成/未完成及服务器版本；未完成也是有效状态，不能仅靠删除后取并集推断 |
| 待同步操作 | 当前 UID 下尚未获服务器确认的修改，包含完成和取消；不属于访客数据 |
| 显示数量 | 地图数量随 DLC 范围改变；迁移、备份和同步覆盖全部 136 座，不能遗漏隐藏 DLC |
| JSON 备份 | 保留现有 v1 可用格式与 ID 校验；导出明确标识当前来源是访客还是账号 |

访客、账号 A、账号 B 的缓存、队列与备份必须可区分。切换身份时不能把旧身份的画面或异步请求结果当成新身份的进度。账号会话失效时暂停云写入；界面提示重新登录，不自动把账号进度保存为访客。

退出后恢复原访客进度；未同步的账号操作保留在该 UID 的持久队列中，重新登录同账号后可恢复。退出前提示尚有待同步项，允许用户退出；不能因退出清空队列，也不能继续用已退出身份发送写入。失败退出不伪称已退出。

## 3. 主流程与异常流程

### 3.1 访客及未配置环境（R1、R7）

启动时先恢复 v1 访客进度和本地偏好。没有 Supabase 配置时，地图、详情、筛选、完成操作、JSON 备份均正常可用；账号入口说明“云同步尚未配置”，不给出可成功登录的假入口或模拟云已同步。浏览器存储异常时允许浏览与当前会话操作，但明确“尚未保存到本机”，提供重试和导出。

### 3.2 邮箱验证码（R2）

用户输入邮箱，请求验证码，收到邮件后输入验证码完成认证。请求中防重复提交；成功发送请求只能提示“验证码已发送/请查收”，不能表示已登录。输入格式、无效或过期验证码、请求限流、邮件发送失败、网络失败均给出可操作提示，可修改邮箱或重试。验证码长度、有效期及重发间隔与实际服务配置一致，由技术方案确定，不虚构固定值。

认证成功后进入“账号进度加载中”，完成云端读取后才进入可写状态。未收到邮件或认证失败可返回访客，访客进度保持不变。

### 3.3 GitHub OAuth 与会话恢复（R2）

点击 GitHub 登录后说明正在跳转；官方回调返回有效认证会话后读取当前 UID 的云进度。用户取消授权、OAuth 返回错误、回调会话无效或网络失败均回到可操作页面并提供重试/继续访客。仅有 URL 回调参数不等于成功登录。

本机地址和 Pages `/zelda_map/` 子路径均有明确回调入口；处理认证返回数据后正确恢复应用路由，不能与现有 hash 地图/详情路由冲突。刷新恢复会话也走相同的 UID 识别和加载流程。邮箱登录与 GitHub 登录是否由平台识别为同一 UID，以实际认证结果为准；本版不承诺自动合并不同 UID 的账号。

### 3.4 账号加载、修改与同步（R3、R4、R7）

登录后暂停访客数据向云端的自动写入。云记录读取成功之前，不把空集合、访客集合或未确认缓存上传为账号完整进度。

首次登录当前设备且云端读取失败：展示“账号进度暂未加载”，允许重试或退出回访客；不得用空账号状态接受修改后覆盖云端。已有同 UID 的已加载缓存时，可显示缓存并清楚注明离线/未更新；修改保留到该 UID 队列，恢复连接后先校验服务器版本再同步。缓存可编辑条件和加载状态由技术方案明确，不能绕过首次读取屏障。

完成/取消操作先尝试持久保存到当前身份的本机缓存/队列，再同步云端。云端确认前显示“同步中”或“本机已保存，待同步”。刷新和离线重启后待同步项仍可恢复；连接恢复或用户重试后继续。已确认操作不能重复改变结果；连续快速点击以用户最终目标为准，不能由旧响应覆盖新操作。

离线、超时、认证失效、数据库拒绝与本机保存失败分别有真实状态及重试/导出路径。仅网络请求返回成功不够：服务器必须确认目标记录及版本，当前身份下所有修改已确认、无冲突，才可显示“云端已同步”。

### 3.5 逐座版本冲突（R5）

每座修改带其已知服务器版本。另一设备先改同一座后，本设备不能静默覆盖。界面展示冲突神庙名称、ID、本机目标、云端状态，可明确选择“保留本机”或“采用云端”，并解释影响。选本机时仍需基于最新服务器版本提交；再次变化继续提示冲突。选云端只消除该座对应待同步操作，不丢失其他座的待同步项。

不同神庙的并发修改可各自保留。同座取消完成必须同步为未完成；不能以 completedIds 简单并集使取消复活。冲突预览只使用安全名称/地区等信息，不透露解法或奖励。

### 3.6 首次迁移与备份恢复（R6）

当前 UID 云端读取成功、且本 origin 有 v1 访客进度时，提供迁移预览；不自动上传。用户可以稍后处理，继续使用已加载账号进度；访客原数据仍保留，设置中可再次开启迁移。

预览列出来源（本机访客或导入文件）、本地完成数、云端完成数、重合数，以及选择后的总数和受影响数量。迁移覆盖全部 136 座，与 DLC 显示范围无关。

| 选择 | 结果与提示 |
| --- | --- |
| 合并 | 用户明确确认后，保留云端已完成并加入本地已完成；这是一次迁移选择，不作为日常同步规则 |
| 替换 | 以来源完整集合为账号目标；云端有而来源没有的神庙将变为未完成，预览必须展示将取消数量 |
| 取消/稍后 | 不发迁移写入、不改访客、不改账号当前云进度 |

确认前保存来源原数据及账号操作前快照，含归属、时间和可恢复记录；需要保留已有未同步操作，不能被迁移静默丢弃。技术可选择在待同步项处理完前暂不执行迁移，或将其纳入预览，必须明确可见。无法建立备份时禁止开始替换；可提示先导出备份再重新尝试。

迁移采用当前服务器版本写入。预览后云端已变化时重新预览或进入逐座冲突处理，不能凭旧预览强行覆盖。迁移中断或部分成功保留备份和未确认操作，提示实际进展，不报整批成功；重试不会重复误改已完成项。

设置提供迁移/导入前备份的导出与恢复预览。恢复须说明目标身份及将改动数量，用户确认后按相同版本冲突与同步规则执行；不自动把账号快照恢复到访客或另一个 UID。原访客 v1 存储保持可读，账号迁移不清除它。

JSON 导入继续校验格式、游戏、已知 ID、大小、重复 ID 与数据版本差异；导入目标明确是当前访客或账号。账号导入遵循上述云端加载、备份及冲突约束。跨 origin（本机→Pages）仍通过导出/导入，不能声称浏览器会自动发现其他 origin 的本地数据。

## 4. 状态与展示（R7）

身份与状态在地图、详情、设置均能查明；短暂 toast 不作为唯一保存证据。地图主操作不因登录宣传占据大幅空间，具体布局交给 UIUX。

| 状态 | 可观察事实 | 禁止的提示 |
| --- | --- | --- |
| 访客 · 本机已保存 | 当前访客修改持久写入并验证成功 | 云端已同步 |
| 账号进度加载中 | 会话有效，首次云端读取未完成；修改受保护 | 已同步、空进度已恢复 |
| 账号 · 同步中 | 当前 UID 有正在等待确认的请求 | 云端已保存 |
| 账号 · 云端已同步 | 当前 UID 全部目标获服务器确认，无待同步/失败/冲突 | 仅凭登录成功即展示 |
| 账号 · 离线待同步 | 队列持久保存，网络不可用或暂不可达 | 修改丢失、云端已同步 |
| 同步失败 | 有未确认操作，显示重试与简短原因 | 成功保存 |
| 需处理冲突 | 至少一座存在版本冲突，提供入口及数量 | 已同步 |
| 尚未保存到本机 | 持久存储失败，仅会话保留；可导出/重试 | 本机已保存、可刷新安全恢复 |

同时有多种状态时，以未保存/冲突/失败等需要处理的情况优先，显示待同步数量；不得通过颜色作为唯一信息。加载、发送、重试提供进行中反馈；错误文本三语可理解，键盘可操作。

| R6 迁移及恢复 | 旧 v1 与 v1 JSON 兼容；合并/替换预览数正确；取消零写入；备份失败保护；原访客不删；恢复说明身份；跨 origin 需文件 | 真实云迁移、途中失败重试、替换取消及备份恢复验证；无假批次成功 |
| R7 真实保存提示 | 阻断本地存储、断网、服务器失败、冲突时不报成功；地图/详情/设置身份一致；退出回访客原集合 | 实云响应与界面同步状态一致，失效会话暂停写入 |

测试报告必须区分本机单元/模拟测试、真实项目联调与本人验收。模拟通过只能支撑实现路径，不替代 R2—R6 实云证据。外部依赖未满足时可以交付本机候选及接入材料，但这些实云验收仍为待验证。

## 6. 外部依赖、待验证与实施取舍

必需配置：由用户指定/提供 Supabase 项目 URL 与前端公开可用 key；数据库 schema、版本更新接口及 RLS 规则在该项目执行；邮箱验证码邮件模板、发件/SMTP 能力；GitHub OAuth App、回调 URL、Supabase Auth 允许的本机与 Pages URL。不得取得其他项目密钥、把管理 key 放入前端，或创建付费资源。

尚无实际项目、SMTP 和 OAuth 配置，因此认证送达、RLS、真实版本竞争、跨设备和部署回调均待验证。技术文档须给出配置步骤、环境变量与真实验证清单；配置缺失不阻塞访客功能和候选实现。

技术决定缓存格式、队列压缩/重试策略、版本字段与原子更新方式、恢复快照保留方式；UIUX 决定账号入口、状态位置、预览和冲突交互。允许符合上述不丢数据、不伪报、不串身份约束的最小实现，不承诺独立账号管理、绑定/解绑、密码登录或后台管理界面。

用户验收建议顺序：无配置访客及旧数据 → 两种登录 → 登录/退出身份 → 迁移合并/替换及备份恢复 → 完成/取消和状态 → 离线与冲突 → 原地图回归。实云验证完成前，验收材料明确显示仍缺哪些证据。
