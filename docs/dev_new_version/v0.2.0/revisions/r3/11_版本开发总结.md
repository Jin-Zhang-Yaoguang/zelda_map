# v0.2.0 开发总结（r3，待本人验收）

用户需要同一账号在本机与正式网页恢复神庙进度，并保留访客。当前邮箱注册/密码登录、UID 隔离、云队列/逐座冲突、完成与取消同步、显式旧访客迁移、持久备份及保存状态均已有实现。语言和 DLC 偏好仍在本机，136 神庙和 15 高塔的数据与原体验保留。

登录需求经历 r1 邮箱 OTP+GitHub、r2 无邮件服务的邮箱密码+GitHub，最新 r3 取消 GitHub。旧方案与失败/通过证据保留，当前不再要求 OAuth 凭据、邮件服务或验证码。注册至少 8 字符、确认密码，只有有效 session/UID 才登录；云初读成功前禁写。密码由 Supabase Auth 处理，不进进度/备份/env，邮箱不验证归属且无邮件找回。

r3 六源码删除 GitHub 入口/接口/专有回跳和视图恢复；邮箱两方法逐字不变，controller 仅删对应调用。CAS、队列、UID隔离、迁移、SQL、依赖不扩大改动。实际角色：此前产品/UI/技术/前后端建立方案，当前前端执行收敛删除，独立 QA 定向测试，看门狗独立静审/构建；主代理维护需求与状态、实际配置核对和本人交接。

现有 r2 本机认证 7 组、浏览器 19 组及编辑清错误两组有证据；有限实云 API 10 组通过，涵盖两个合成账号密码身份、真实 JWT/RPC、独立客户端完成取消、重放/CAS、合成 136 项迁移。r3 独立 typecheck、根/Pages/无配置三个构建和 6 组定向浏览器测试全部通过，浏览器错误为空。独立静审与隔离构建也已通过，最终巡检输入绑定见 09 最新节。旧测试不能扩大到实体跨设备或本人实际数据；未变 SQL/引擎不重复测试制造进度。

Supabase Free 项目、SQL、权限元数据、匿名拒绝、公开构建变量、Confirm OFF/最低8均完成。当前公开 Auth 读回 GitHub=false，取消配置无需额外凭据动作。原访客和云数据保留，登录不会自动上传原访客。

正式网站仍 v0.1.0；当前 dev/v0.2.0 没有提交/推送/合并/部署。独立检查完成后交本人验收真实注册、云保存及跨浏览器体验，再处理发布；整版尚未完成，不用配置授权或代理结论代签。
