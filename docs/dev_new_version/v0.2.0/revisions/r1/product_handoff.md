# v0.2.0 产品交接

角色：product_manager。日期：2026-10-11。主文档：`02_PRD.md`。覆盖需求 R1—R8；状态为设计口径已整理，尚无产品验收及实云成功结论。

## UIUX / 前端

- 同时提供邮箱验证码和 GitHub 登录；账号成功后先展示进度加载状态，地图/详情/设置显示一致身份与保存状态。
- 访客与账号分开。退出回原访客集合，待同步账号数据只保留于其 UID；会话失效不能自动变成访客并覆盖本地旧进度。
- 迁移预览包含来源、本地/云端/重合数量、合并或替换的结果及取消完成数量；默认不执行，保留取消/稍后。恢复预览要说明目标身份。
- 冲突逐座显示安全名称、ID、本机和云端状态，明确保留本机/采用云端，不剧透。
- 无配置入口说明尚未配置；本地写失败不能出现成功 toast。真实状态及错误三语齐备，错误/待同步可持续查到，不能只靠颜色。

## 技术 / 后端

- 云端读取屏障：首次账号云加载失败不允许以空集合或访客集合写回；同 UID 已加载缓存离线编辑仍需版本校验。
- UID+game_id+shrine_id 隔离，服务端 RLS 强制限制；完成与取消均是同步目标。缓存/队列/备份按身份隔离，旧异步结果不应用到新身份。
- 每座基于服务器版本更新，冲突不得默认为并集或全覆盖；用户选本机也需再次校验版本。
- v1 原访客数据保留。迁移/替换/恢复先备份，再按版本执行；中断和部分成功保留实际状态，重试可恢复。不把账号快照自动导入访客或另一 UID。
- 未同步项退出不丢失；迁移与已有待同步队列的关系可选择“先处理队列”或“纳入预览”，请在技术方案明确，不能静默丢弃。
- 语言和 DLC 显示仍属本机偏好，云端只存神庙进度。数据、缓存、队列结构和恢复留存由技术选择最小实现。
- 准备 Supabase/数据库/RLS/SMTP/验证码模板/GitHub OAuth/本机及 Pages 回调配置材料；当前项目与认证配置均未提供。

## 测试 / 主代理

R1—R8 的可观察条件见 PRD 第 5 节。重点准备：加载慢/失败零覆盖；A→退出→访客→B 身份切换；快速完成再取消；离线刷新；两设备同座和不同座并发；迁移替换导致取消；备份失败；部分成功重试；恢复中出现新云版本；本地存储异常成功提示排除。

测试结果分别标注“本机模拟已验证”“真实项目已验证”“待外部配置”。RLS 必须有两个真实账号的越权拒绝证据，邮箱/GitHub/跨设备须真实验证；模拟数据不代表真实联调。

待协调者确认的实施取舍：账号已加载缓存离线可编辑条件；迁移时已有待同步项的处理方式；快照留存与恢复入口的最小形式。以上不要求新增用户决策，只要求方案可核查地满足 PRD。

本版不更新正式记忆、不发布、不改 v0.1.0 生产。无长期记忆候选文件写入授权；可供协调者后续收尾的候选事实是“用户明确邮箱验证码+GitHub均支持，仍保留独立访客模式”，来源 `01_需求文档.md`，适用 v0.2.0，当前实现与真实运行尚待验证。
