# v0.2.0 r2 邮箱密码产品交接

角色：product_manager。日期：2026-10-11。独占产物：`02_PRD.md`、本文；未改代码、配置和其他角色文档。分支 dev/v0.2.0，基线 2686aa1。来源：`01_需求文档.md` r2 真人原话「先不上线邮箱服务吧。直接用户自己输入邮箱和密码即可使用。」

## 产品决定

- **已确认范围**：R2 邮箱注册＋密码登录替代 OTP；保留 GitHub 和访客。R1/R3—R8 的加载屏障、逐座 CAS、身份隔离、迁移备份与真实保存状态不变。
- **产品约束**：明确登录/注册模式，默认登录；注册增加确认密码，提交中锁定认证动作。登录不自动注册。邮箱仅是标识，不证明邮箱归属；注册前说明当前无邮件找回密码。无验证码、重发、邮件确认及找回入口。
- **策略建议**：注册最低 8 字符，技术读取实际后台策略后对齐；更严格时按后台规则，不能降低保护。登录只要求密码非空，保留密码原始字符。邮箱去首尾空白；允许粘贴及密码管理器填写。
- **安全与状态**：密码和确认密码仅保留在当前表单内存，关闭/切模式/成功后清除。密码不进 env、IDB、local/session storage、队列、备份、日志或错误细节。仅真实 session＋UID 才算登录；云初读成功前不可写。数据库密码不是网页密码。
- **有条件成立**：Confirm email 关闭后才能无需邮件直接注册。当前尚未关闭，必须实现确认仍启用或无 session 的诚实异常。主代理准备可审查代码/表单后按浏览器规则当场请真人确认该开关操作；本角色未取得或执行该确认。
- **待验证**：真实密码策略、注册/登录、GitHub、跨账号与跨设备完整链路、r2 本人验收。协调者已核实项目和数据库保护，但不能据此宣称认证或云整体验证通过。r1 存 `revisions/r1/`，其通过结论非 r2 通过。

## UIUX / 前端增量任务

1. 将 OTP 两步表单改为登录/注册两模式，注册多一个确认密码，保留 GitHub 和继续访客。三语补齐标题、按钮、字段、强度要求、邮箱标识及无找回说明；使用正确的 email/current-password/new-password 自动填充语义。
2. 注册前端无效时就地提示，禁止请求；请求中防重复、锁定模式切换和其他认证动作。关闭、切模式、成功清除密码；认证响应只展示安全错误文本。
3. 覆盖错误凭据、重复注册、后台密码规则、限流、网络不明和仍需邮箱确认。无 session 不出现已登录/已同步，不跳入迁移。不能提示等待验证码或要求完成已暂停的邮件流程。
4. 成功后进入已有账号加载流程。地图、详情、设置身份一致；退出、A→访客→B、会话失效按原 UID 隔离规则，密码表单改动不影响访客旧数据和账号队列。

## 技术 / 后端增量任务

1. 替换认证层、controller 和接口类型中的 OTP 调用/状态为显式注册与密码登录；注册、登录均校验 Supabase 返回 session 与 UID，再沿用 switchIdentity/首次云读取屏障。不能以 user 单独存在触发登录成功。
2. 读取实际密码策略，确认前端一致。Supabase 错误归一化为上述安全、可操作分类；响应不能证实重复账号时，不假称账号已注册或泄露内部返回。未知错误保留通用提示，禁止打印请求密码。
3. 验证表单值只用于认证提交，绝不进入进度 envelope、transfer、snapshot、持久 store 或日志。现有 Supabase SDK 会话持久化保存的是认证会话，不得额外保存密码。仅密码认证路径调整，RPC、表结构和 R3—R8 契约沿用。
4. 准备 Confirm email 开关读回、密码策略、Auth URLs 与 GitHub 接入核查清单。无邮件时不引入 SMTP 或模板配置；不开自动重试注册/登录，限流不伪造倒计时。
