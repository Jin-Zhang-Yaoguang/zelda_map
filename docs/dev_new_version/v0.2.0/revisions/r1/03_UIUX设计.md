## 3. 登录与退出（R1、R2、R7）

### 未配置及访客

缺配置：地图正常guest使用，真实状态为“访客 · 本机已保存”；账户节“云端同步暂未配置。可以继续使用访客模式。”邮箱、OTP、GitHub不呈现为可执行登录控件，不放重试网络按钮，不要求用户提供密钥。备份、导入、显示设置正常使用。

有配置：说明“登录后可同步账户进度。当前访客进度会保留，迁移前可预览。”邮箱有可见label，`type=email`、`autocomplete=email`。主按钮“发送验证码”，次按钮“使用 GitHub 登录”。guest不用点击额外“继续访客”才能看地图。

### 邮箱OTP

1. 邮箱非法：就地错误、`aria-invalid=true`，焦点进邮箱。发送中“发送中…”，禁重复发送；邮箱暂不可改。
2. 发信成功：“验证码已发送至 {email}”，焦点进单一验证码输入。允许整段粘贴，`autocomplete=one-time-code`、`inputmode=numeric`；maxlength按项目实际OTP长度，未验证前不写死“6位”。
3. “确认登录”主按钮，“重新发送”“更换邮箱”次操作。倒计时按真实限制，不承诺邮件到达时间；换邮箱清验证码/错误，回邮箱步骤。
4. 验证中“验证中…”，禁重复提交。错误保留输入可编辑：无效/过期“验证码无效或已过期，请检查或重新发送”；限流“请求过于频繁，请稍后再试”；网络“暂时无法连接，请稍后重试”。不展示原始堆栈/token。
5. 成功先显示真实身份及“正在读取账户进度”，不直接“云端已同步”。当前设备从未成功初始化该UID时，读完前完成、导入、迁移禁用，并有“读取账户进度后可修改”说明；地图和详情可浏览。有该UID曾成功加载的可信缓存时，读取失败可编辑离线缓存并持久入该UID队列，但必须标“缓存未更新”，恢复后先校验版本；迁移仍需本次云读成功。

Enter只提交当前表单，不触发地图操作。失败通过就地alert播报一次，不叠重复toast。

### GitHub及回调

点击“正在前往 GitHub…”，一次跳转。保留应用内部返回路由、语言；回调清理认证参数后回原地图/详情/设置，不改选择。返回位置仅应用内路由。OAuth回调“正在确认登录…”，会话确认后转账户初始化。拒绝/失败/无效回调：“GitHub 登录未完成，可重试或继续使用访客模式”，guest记录保留。清理认证参数不能误删神庙详情hash；Pages子路径专门验证。

### 账户、退出及失效

账户节显示完整身份、真实保存状态、待同步项数、冲突数、最近服务端确认时间（有依据才显示）。“重试同步”“查看冲突”“迁移访客进度”“退出登录”按状态出现；进行中禁重复操作，可返回地图。

退出旁说明“退出后返回访客进度。当前账户的待同步记录会保留，重新登录此账户可继续。”正常退出不再增加确认。退出中禁重入；实际清会话及切guest后才标“访客”。失败保留account，提示“退出未完成，请重试”。guest恢复原值，账户不写进guest；A/B切换不展示别的账户记录。

会话失效停止云写：“登录已失效，请重新登录。未同步记录仍保留在此设备。”完成按钮按状态禁用；不得悄悄把account编辑改存guest或交给新UID。

## 4. 保存反馈（R4、R5、R7）

身份和保存独立；状态条、设置、完成操作共用状态源。勾可响应本机修改，但远端确认前不能云成功。队列持久化失败优先警告，不得称“离线待同步”。

| 条件 | 短状态 | 详情/恢复 |
| --- | --- | --- |
| guest持久成功 | 本机已保存 | 当前浏览器；导出 |
| guest/account本机持久失败 | 本次修改未保存 | 重试/导出；刷新可能丢失未保存修改 |
| 本机原记录损坏 | 本机记录需恢复 | 沿用原记录导出/恢复，不直接覆盖 |
| 会话尚未确认 | 正在确认登录… | 不用guest成功暗示恢复完成 |
| 云初始化中 | 正在读取账户进度… | 禁写，可浏览 |
| 初始化失败，有本UID已加载缓存 | 无法读取云端进度 | 展示该UID缓存及时间；不标最新；允许离线编辑并入本UID队列，重试 |
| 初始化失败，无本UID缓存 | 无法读取账户进度 | 完成/导入/迁移禁用；重试/退出 |
| 队列已持久，离线 | 离线待同步 · {n}项 | 已存此设备，联网后重试；导出 |
| 队列已持久，远端进行中 | 同步中 · {n}项 | 本机已存，正同步当前账户 |
| 全部远端确认，无队列/冲突 | 云端已同步 | 最近确认时间；在线不等于同步 |
| 远端拒绝/写失败 | 同步失败 · {n}项 | 说明本机是否保存；重试/导出 |
| 同座版本不一致 | 有 {n} 座进度冲突 | 查看；其他独立神庙继续同步 |
| 会话失效 | 请重新登录 | 保留原UID队列；登录入口 |

短状态优先级：本次修改未保存 → 请重新登录 → 有冲突 → 同步失败 → 离线待同步 → 同步中 → 云端已同步。设置保留其他非零待处理项；偏好保存异常独立显示。空云真实0条不能清guest、UID缓存或队列。

完成toast按结果：“已标记完成 · 本机已保存”“已取消完成 · 等待同步”“本次修改未保存”。撤销只针对当前模式该座；退出/UID切换关闭旧toast与撤销。成功`role=status`、`aria-live=polite`，播报一次；失败/冲突持续显示，不能只依赖短toast。

## 5. 迁移与JSON导入（R6）

登录不自动合并。账户初始化完成、guest有有效记录时，在账户节显示“此浏览器有 {n} 座访客完成记录。可以预览后迁移至 {identity}。”点“预览迁移”主动开dialog；“暂不迁移”收提醒，设置仍有入口。账户地图只算account。

迁移dialog560px、最大高`100dvh-28px`、手机宽减28px。标题“迁移访客进度”，目标账户完整可见；三列/手机三行“访客原记录 / 当前账户 / 迁移后”，补充“重合 {n} 座”及受影响数量。DLC隐藏仍参加，注明“包含隐藏的DLC记录”。有当前UID待同步/冲突时显示“请先完成当前账户的同步或处理冲突，再迁移”，确认暂不可用；旧队列不被迁移丢弃。两项原生radio不预选：

- 合并已完成记录：“保留账户已完成记录，并加入访客已完成记录”；显示新增数、取消0和最终数。仅用户显式迁移可并集，日常取消和CAS冲突不套用。
- 用访客记录替换：“账户将与这份访客记录一致，其他账户完成记录会被取消”；显示新增数、取消数、最终数。

差异列表默认展开；每行名称/地区/DLC/当前→结果。136座规模内部滚动，不分页隐藏变化；无变化“进度一致，无需迁移”，不发空写入。底部“取消”“导出迁移前备份”“确认合并/确认替换”；方法已选、预览完、账户未变、无原待同步/冲突、备份成功才可确认。

操作前备份标明guest源和目标账户，不混成身份不明文件，guest原记录保留。迁移和云端替换必须持久快照成功，失败禁确认：“操作前备份未能保存，请重试。当前进度未被替换。”不沿用v1仅会话恢复绕过云保护。下载完成仅称“已发起下载”，不声称文件已落盘；下载仅额外备份，不能自动替代持久快照。此取舍已由主代理确认。

提交“正在迁移…”，禁重复。云版本变更/CAS失败：读取新差异，“账户进度已更新，请核对新的预览”，重新选择/确认，不能旧预览强制覆盖。迁移整批提交；任一版本冲突时，整批零写入，保留待处理批次并重新核对。日常逐座标记可按实际记录分别显示待同步或冲突，不能将其状态用于声称迁移部分成功。全远端确认才“迁移已完成 · 云端已同步”；只有队列已存为“迁移已在本机保存 · 等待同步”。收起dialog不撤回已提交操作，设置保留进展。

JSON导入沿用校验、旧记录备份和预览，明确目标guest或当前account。未知ID、版本、重复、坏文件保留既有反馈。account未初始化不可导入；account替换同样显示新增/取消、备份及CAS保护。跨origin：“在原页面导出，再在这里导入”，登录不宣称自行读取别的origin。

设置保留“迁移/导入前备份”区：来源guest或账户身份、备份时间、完成数，“导出此备份”“预览恢复”。恢复dialog显示备份原归属与当前目标、将新增/取消的逐座差异，不能自动恢复到guest或其他UID。账户快照不属于当前UID时阻止账户直接恢复，说明重新登录原账户后操作；同UID恢复仍需云读成功、无待同步/冲突、再次操作前备份与CAS。guest恢复沿用v1流程，目标必须明确为guest。

## 6. 逐座冲突（R5）

状态条/设置持续提供“查看冲突（{n}）”。dialog标题“处理进度冲突”，说明“这座神庙在其他设备上发生了修改。请选择要保留的状态。”每座名称/地区、次级小字稳定ID、本机值、云最新值；可信时间有则显示，不替用户按时间裁决。ID仅供准确辨认同名记录，不提升为主标题。

每座radio“保留本机：已完成/未完成”“采用云端：已完成/未完成”，不预选；“应用所选状态”支持逐座应用，未选保留，并显示剩余数。“稍后处理”不丢队列；无冲突“没有待处理冲突”。

应用只禁提交行。保留本机仍以最新云版本校验；云再变就更新两值、清旧选择，“这座神庙又有更新，请重新选择”。采用云更新该UID本机状态并移除对应待同步操作。只作用当前shrine；不复活其他座取消状态，不添加攻略信息。关闭返回触发点，Esc不表示采用云端。

## 7. 响应式与无障碍

验证1440/608/360/390px。桌面设置保持原830px外宽/48px边距；手机20px边距，输入全宽、按钮可纵排，最低44px。长邮箱`overflow-wrap:anywhere`；状态条可两行，不能把地图标记遮到面板后仍hover。

复用modal：`role=dialog`、`aria-modal=true`、关联标题/描述，背景不可交互。初焦点标题（`tabindex=-1`）/取消，不到替换主按钮；Tab/Shift+Tab围栏，Esc收起，回触发点。进行中收起不撤销任务，状态区继续展示结果。手机软键盘和400%缩放可滚动达底部按钮，无水平滚动。

radio用fieldset/legend及方向键；输入真实label、错误`aria-describedby`；loading文字及`aria-busy`，减少动态效果时无旋转。禁用有可见原因；title不能唯一提示。正常polite、失败alert、倒计时不每秒播报。焦点环沿用2px蓝色，次文字对比需实测。

## 10. 主代理确认的OAuth视图恢复实施补充

真实GitHub跳转会整页重载。主代理已批准App在调用原controller.signInGithub前，临时保存query、地区/完成筛选、selectedId、面板状态、地图中心/缩放与返回焦点；不包含任何进度、UID、令牌或认证字段。该视图记录限当前sessionStorage，schemaVersion 1、15分钟TTL，回调根路径读取即清理；字段、已知地区/神庙ID、有限坐标和合法zoom校验失败则回默认视图，不妨碍访客使用。

MapCanvas的可选initialView只用于首次有效恢复，不以所选神庙重新定位覆盖保存的中心；设置/详情内地图隐藏时不把隐藏容器的临时相机数据写回最后可见视图。OAuth错误/取消仍保留原guest进度，auth模块的hash清理/PKCE契约不变。真实认证与跨设备验证仍按实际Supabase接入证据判断，模拟重载只能证明视图恢复。
