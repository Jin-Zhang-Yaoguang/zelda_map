# v0.2.0 技术方案（当前 r3）

2026-10-11。基线 2686aa1，分支 dev/v0.2.0。用户取消 GitHub，仅邮箱注册/密码登录；主代理按已有专业方案收敛删除范围，前端代理统一负责六源码，独立 QA 与看门狗验证。r2 全文留在 revisions/r2，不再作为当前 GitHub 接入要求。

## 技术与身份契约

沿用 React/TypeScript/Vite/Leaflet SPA，Supabase SDK 2.117.3 负责身份，两个 PostgreSQL RPC 同步，IndexedDB 存账号缓存、队列与备份。语言/DLC偏好本机保存。136 神庙、15 高塔、无聚合、缩放阈值及不剧透不变。

公开 Auth 与 controller 只提供 `signUpEmailPassword(email,password)`、`signInEmailPassword(email,password)`、`signOut()`；Auth 返回有效 AccountIdentity，controller 返回 Promise<void>。删除 signInGithub、OAuth callback/code 兑换、return-hash、App OAuth 视图保存/恢复；不新增替代认证路径，不改官方 SDK 持久会话与现有 PKCE 配置。

只认真实 session 的非空 user.id/access_token；只有 user 或无有效 session 报 sessionNotEstablished，不猜测注册结果。明确 email_not_confirmed 才提示确认未完成。invalidCredentials、弱密码、明确重复、限流和网络错误分类保留。不用 Auth 裸 401 将访客标成失效；真实会话错误或 RPC 身份失效才暂停当前 UID 写入。

邮箱 trim，密码原样；注册最低 8、确认密码只在组件中校验，登录只非空。密码仅表单/请求内存，成功、切模式、身份变化、失效和卸载清除；不写快照、IDB、队列、备份、env或日志。编辑清本表单旧 Auth 错误，不掩盖身份/同步/存储/迁移错误。异步认证受生命周期与身份 epoch 保护，旧 Promise 不切回旧 UID。

AccountSnapshot 的 authPhase、ready、completedIds、saveState、pendingCount、conflicts、error、backups 不变。AccountIdentity 仍含 uid/email/provider/displayName，归属仅以 uid 决定；provider 为服务返回信息，不代表可用登录入口。前端不按邮箱合并账号。

## 同步与迁移（R3—R8 原契约）

- project/uid/game 分区缓存、队列与备份；访客使用原 v1 键，不把账号 Set 写回访客。退出恢复原访客，待同步项保留原 UID。
- 首次云读取成功前禁写；有同 UID 可信缓存才可离线编辑。异步结果必须仍属于当前身份。
- 完成/取消先持久保存缓存与队列，再发云；服务确认、队列清空且无冲突才显示 cloudSynced。网络、存储、限流与会话失效分别提示。
- RPC 使用 revision CAS/request UUID 收据；陈旧更新不能复活取消，重放不重复增版本。冲突逐座明确选择，再次远端变化必须重新选择。
- 访客/JSON/备份恢复先预览合并或替换；用户确认后，IDB 同事务保存原始备份与持久任务，再提交全部 136 项。批次冲突零进度写入，原访客字符串保留，隐藏 DLC 不漏迁移。
- 备份仅属于当前 UID；对话保留显式发起控件的返回焦点与身份 epoch 保护。

SQL 沿用 private shrine_progress/progress_receipts、RLS、owner policy、表直接 DML 禁止、仅 authenticated 可执行 SECURITY DEFINER RPC 与空 search_path。完整算法以源码和 migration 为准，不重复迁移、不建密码表/alias。
