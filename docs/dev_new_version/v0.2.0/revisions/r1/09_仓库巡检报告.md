## 数据与账号安全链

1. `supabase/migrations/202610110001_account_progress.sql`：两个表位于 private schema；对 public/anon/authenticated 撤销直接表权限并开启 owner RLS。两个 RPC 的 `SECURITY DEFINER` 固定空 search_path、全限定表/函数，入口读取 `auth.uid()` 且拒绝 null；所有进度和收据查询均约束该 UID。只向 authenticated 授予 EXECUTE。函数 owner 可以绕过 RLS，故内部 UID 条件和 ACL 是独立授权边界，不能将 RPC 成功冒充 RLS 证明。
2. 取消完成写 false 增 revision，不删除记录。每批 CAS 在任何写入前全量检查；136 座迁移出现一处版本冲突即零进度写入。账户/游戏事务锁串行化首写及 CAS；收据与进度同事务，相同 UID/game/request UUID 的原始 payload 只执行一次，不同 payload 拒绝，冲突重选必须新 UUID。
3. `cloud/repository.ts` 每次 RPC 前核对 session UID 与预期 UID，并把当次 token 明确绑定 Authorization；请求没有用户可指定的 owner 参数。返回值严格校验 ID、布尔、revision、日期和 request ID。controller 以 UID/epoch 保护画面，迟到 ACK 只更新原 UID 的缓存，不能污染新账号或 guest。
4. IndexedDB key 含 project/UID/game，envelope 将 cache、loaded、overlay、immutable job、backup 放进同一事务。commit 失败不发送本次云任务；损坏数据拒绝覆盖。成功读取云端的 loaded 缓存才允许离线编辑；首次读取失败只读。队列原 UUID/payload 供响应丢失重放，序列号保护快速完成/取消的后续意图。
5. 迁移先确认当前 UID、无 pending/conflict、真实云预览和源原文，再用单事务保存操作前备份和完整 136 项任务；持久化失败不启动迁移。guest v1 原记录不被删除或改写；备份恢复仍走同 UID 新预览/CAS。账号操作不是日常并集同步。
6. Auth 使用 PKCE、显式单次兑换、受控 hash 和实际根地址。临时 OAuth 视图只有筛选/位置等 UI 状态，schema、TTL、有限坐标和已知 ID 校验，无进度/令牌/外部 returnTo。登录成功和本机排队都不能单独显示云已同步；云读取/ACK、无待传/冲突且缓存提交后才显示同步。

上述源码结论与 QA 的 PGlite、fake IndexedDB、受控 SDK/浏览器层相互核对。`sql-results.json` 的 RLS 正反例用隔离库临时 grant 和非超级用户执行，不能误称真实 Supabase JWT。`engine-results.json` 是修前失败记录，应保留；E09 的解除依据是 [local 修后](evidence/engine-conflict-local-final.json)、[cloud 修后](evidence/engine-conflict-cloud-after-fix.json)，并非覆盖失败历史。OAuth root/Pages 视图恢复有 [独立浏览器修后证据](evidence/browser-oauth-view-final.json)，仍为受控 GoTrue。
