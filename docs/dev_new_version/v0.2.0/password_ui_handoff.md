# v0.2.0 r2 邮箱密码 UI 交接

日期：2026-10-11；实际角色 ui_ux。依据当前 `01_需求文档.md`、`02_PRD.md`、`password_product_handoff.md` 与 `03_UIUX设计.md` §11。仅修订设计文档，无代码/云配置变更、实现验收或本人批准。r1 的 `ui_handoff.md` 与 OTP 方案是历史，快照在 `revisions/r1/`。

## 前端落点

- `AccountPanel`：保留账户节和原按钮/输入风格，用登录/注册模式替代 OTP 两步。默认登录；一个邮箱、密码，注册增加确认密码。使用普通模式按钮和 `aria-pressed`，唯一 submit 是当前主按钮；GitHub、模式、继续访客是 button。访客返回地图，旧进度与旧 UID 队列保留。
- 表单局部状态建议：`mode`、`email`、`password`、`confirmPassword`、`busy`、字段/认证安全错误；可选 `passwordVisible`。邮箱提交 trim，密码原样；登录只非空，注册重复匹配＋与实际后台策略对齐（8字符暂为产品建议）。失败保留当前表单内存供修正，禁止打印输入和错误原始响应。
- 邮箱 `type=email / autocomplete=email`；密码 `type=password`，登录 `current-password`，注册与确认 `new-password`。粘贴和密码管理器可用；可选显隐按钮独立可访问名称，不提交。所有字段 label、关联说明及错误明确。
- 请求中展示正在登录/注册，字段和所有认证动作暂禁，处理函数也防重入；不自动重试。成功、切模式、关闭/离开设置、身份切换清两项密码、显隐和旧错误。局部字段不得进入 controller 快照、视图记录、队列、备份、存储或日志。旧请求不能在离开/切UID后恢复旧表单错误或回切身份。
- 真实 session＋UID 后清敏感字段，沿用账号初读；user 无 session 不算登录、不触发迁移/账号写。明确邮箱未确认或已核实仍要求确认时用 §11 三语诚实提示；原因未知仅称未建立会话。注册前静态说明邮箱是标识、目前无邮件找回；没有验证码、重发、确认邮件或找回入口。
- `App/Settings`、`AccountBackups`、迁移/恢复/冲突：R1/R3—R8 原契约不变，身份与保存分别显示；异步操作必须发起前捕获真实触发控件，保留现有显式传递与 `returnFocus`，关闭返回有效控件或账户节。不能用异步结束时的活动元素重新取来源。

## 状态文案与交互

完整三语基线见 03 §11.3。错误合并为凭据错误、明确重复账号、实际密码要求、限流、网络未完成、确认未完成、无session；不得依据含糊响应判断账号已存在或注册成功。字段校验聚焦首个无效字段；后台失败播报一次并保持可编辑，模式切换清旧错误。注册结果不明可建议尝试登录，不自动切换/注册。

390/360px 全宽输入和44px触控，三语长文案可换行；键盘弹出仍可滚动到确认密码/错误/主按钮。Tab 顺序：模式→邮箱→密码→确认密码（注册）→提交→GitHub→访客；可选显隐跟对应密码。Enter 只提交当前表单，普通按钮不触发提交。成功和身份变化不聚焦已卸载输入。返回地图/对话焦点沿用原规则。
