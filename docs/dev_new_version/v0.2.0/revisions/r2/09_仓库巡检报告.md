## 守护链核对

1. `auth.ts:12—16、57—74`：只调用官方signUp/signInWithPassword；邮箱trim，密码不改写；注册最低8，登录仅非空。error优先，身份只来自非空session.user.id/access_token。输入邮箱、user-only、HTTP成功都不算登录；无session只提示未建立会话，不猜账号创建/邮箱确认原因。
2. `errors.ts:9—26`：明确凭据/未确认/弱密码/重复code优先；Auth裸401为authFailed；sync/transfer401及明确refresh/session错误为sessionExpired。controller的report只对已有identity转expired，guest失败不伪造过期身份。snapshot/错误文案只存安全类别，不存原服务错误或密码。
3. `controller.ts:103—104、128—130`：认证共用authBusy，退出检查互斥；成功Promise受started/lifecycle/epoch保护，other UID先到、重挂载后的迟到结果不能切回旧身份，同UID事件先到复用加载流程。旧Promise失败不污染新状态。表单还有busyRef/requestEpoch/mounted守护；不新增credentials或旁路会话。
4. 原switchIdentity/current/adopt/pump链保留。切UID清内存overlay/preview后加载独立envelope；迟到ACK只写原UID存储，current(uid,epoch)限制新画面。repository每次核对session预期UID并绑定Authorization。首次云读取/可信同UID缓存屏障、CAS/receipt/备份事务未改，登录本身不显示云已同步。
5. `AccountPanel.tsx:34—42、56—81、95—98`：密码只在当前React表单及本次Auth调用；成功、模式/UID/expired变化、回访客清两项密码，卸载丢弃内存并取消旧UI回报，失败允许原表单修正。无密码写env/local/session/IDB/snapshot/backup/OAuth view/log路径。受控随机密码浏览器扫描支持该结论，不扩称磁盘取证、原生密码管理器已测。
