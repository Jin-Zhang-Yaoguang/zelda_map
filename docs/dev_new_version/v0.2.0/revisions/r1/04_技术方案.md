## 固定 TypeScript 契约

公开路径 `src/lib/sync/types.ts`；工厂路径 `src/lib/sync/controller.ts`。后端可以有私有类型，但前端不得再建另一套状态。

```ts

export type SaveState = 'localSaved' | 'syncing' | 'cloudSynced'
```

getSnapshot在状态不变时保持对象引用，兼容React useSyncExternalStore。subscribe只通知重新读取。start/dispose必须适应StrictMode重复挂载，无第二sender或泄漏订阅。App数据加载完成后创建controller，knownIds固定136神庙，塔不可传入。

访客Set与guest存储仍由App原路径处理。identity存在时展示账号snapshot；ready=false禁止账号编辑并显示加载/未加载，不拿guest或空集合代替账号。只有同UID缓存曾成功云读取、schema与数据均校验通过时，允许离线显示/编辑；cache miss或云初读失败只读。缓存需要loaded标记，pending不等于已有成功baseline。

setComplete/applyTransfer的Promise完成意味着本机事务提交，云确认通过snapshot表示；异常同时reject并写snapshot.error，前端不得无条件toast成功。会话过期保留原UID身份与缓存用于只读/导出，暂停云写入；登录同UID恢复，登录另一UID换为其专属数据。signOut成功才回guest，失败仍显示账号与错误；调用时先暂停sender，失败后可恢复原身份sender。

备份导出由前端使用backups或preview.backup生成现有v1 JSON：操作前账号记录取accountCompletedIds调用makeBackup，文件名/界面标清账号；源记录需要导出时单独以sourceCompletedIds生成v1或导出原raw，不能把TransferBackup混合对象冒充v1。完整身份归属元数据仍保存在IDB用于恢复。preview.backup只是预览快照，apply时才持久化，下载不替代IndexedDB备份。普通当前进度导出继续makeBackup v1，并用文件名/界面说明guest或账号。previewRestore只能读取当前UID所属backup的accountCompletedIds，使用相同迁移预览/CAS流程，不自动跨账号恢复。displayName取服务返回的GitHub用户名等公开身份字段，不能从输入邮箱推定已认证身份。

## Supabase 认证与 Pages 回调

SDK单例设置 `flowType:'pkce'`、`persistSession:true`、`autoRefreshToken:true`、`detectSessionInUrl:false`，由auth模块显式处理回调，防止两次兑换。启动先注册auth listener，再恢复session；INITIAL_SESSION/SIGNED_IN/SIGNED_OUT/TOKEN_REFRESHED都进入统一身份切换。listener只捕获事件并调度后续工作，不在认证回调锁内await其它Supabase调用；同UID刷新token不能重复迁移。[官方认证事件](https://supabase.com/docs/reference/javascript/auth-onauthstatechange)

邮箱使用signInWithOtp，明确 `shouldCreateUser:true` 支持首次注册；Magic Link邮件模板包含 `{{ .Token }}`以发送码。verifyOtp使用email/token/type:'email'。发送成功的user/session为空，只提示查收，不算登录。验证码长度、重发间隔与有效期以项目实际配置为准，前端识别限流/验证码/投递错误。[官方OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless)

GitHub `signInWithOAuth({provider:'github',options:{redirectTo:appRoot}})`；appRoot由 `new URL(import.meta.env.BASE_URL,location.origin)`产生，开发根地址或Pages `/zelda_map/`根地址，不带hash。回调 `?code=...`落在实际index路径，不使用 `/auth/callback`静态不存在路径。发起前保存合法应用hash到sessionStorage；启动遇code时exchangeCodeForSession，遇OAuth error时明确失败。处理完用replaceState清code/error查询参数，恢复受控map/settings/shrine hash；默认回#/settings，不接受外部returnTo。PKCE verifier由SDK同origin保存，缺失、过期、另一浏览器或重复兑换需重登，不补造session。SDK新flowId能力无需本版额外引入，发起OAuth防重复提交。[官方GitHub](https://supabase.com/docs/guides/auth/social-login/auth-github)、[PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow)

signOut用local scope退出当前设备；不localStorage.clear、不清guest或账号队列。token/provider token不写日志、不额外保存GitHub API token。认证存储不可用时明确失败。

## SQL 与 RPC 固定契约

private schema不加入Exposed schemas。两个私有表：

```text
private.shrine_progress
  PK(user_id uuid, game_id text, shrine_id text)
  completed boolean NOT NULL
  revision integer NOT NULL CHECK(revision > 0)
  updated_at timestamptz NOT NULL 由服务器设置
  CHECK(game_id='botw')，shrine_id允许Dungeon000..Dungeon135
private.progress_receipts
  PK(user_id uuid, game_id text, request_id uuid)
  payload jsonb NOT NULL，result jsonb NOT NULL，created_at timestamptz
```

不存在行在CAS中为false/revision=0。取消写false并增加revision，永不依靠删除表达取消。revision为int4正整数，使用服务器递增，不采用设备时间决胜，溢出明确失败。RLS开启，owner策略 `USING/WITH CHECK ((select auth.uid()) IS NOT NULL AND (select auth.uid())=user_id)`；撤销anon/authenticated直接表DML，不允许前端自填UID或直表upsert。

采用托管Supabase可执行的最小public RPC。若使用SECURITY DEFINER，固定search_path=''、全限定表名，函数入口读取auth.uid并拒绝null，每一条select/update/insert/receipt操作均约束内部UID。撤销PUBLIC和anon默认EXECUTE，仅grant authenticated。postgres owner的definer绕过RLS，因此RPC隔离依赖内部owner条件和执行权限；直表RLS与RPC权限分别验证，不将RPC返回结果当成RLS证明。新表不要建立可公开绕过策略的view。[官方函数安全](https://supabase.com/docs/guides/database/functions)、[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)

公开函数及JSON：

```ts
// get_shrine_progress(p_game_id text)
{ rows: [{ shrine_id: string, completed: boolean, revision: number, updated_at: string }] }
// apply_shrine_progress(p_game_id text,p_request_id uuid,p_mutations jsonb)
// mutations: 1..136 唯一ID，布尔completed，非负整数expected_revision
[{ shrine_id: string, completed: boolean, expected_revision: number }]
// applied
{ status: 'applied', request_id: string, rows: [...] }
// conflict（整批零写入）
{ status: 'conflict', request_id: string, conflicts: [
  { shrine_id: string, expected_revision: number,
    current: { shrine_id: string, completed: boolean, revision: number, updated_at: string } }
] }
```

adapter严格校验返回形状与ID、整数、布尔、requestId。缺行冲突current使用revision=0/false、updated_at为空字符串；其它row必须真实时间。SQL错误与网络错误抛出，不将错误视为空集合。

apply事务按UID+game advisory transaction lock或等价账户行锁：检查auth → 校验payload → 取锁 → 查receipt → 全部CAS → 任一失败返回conflict且零进度写入 → 全部写入revision+1 → 写receipt并返回。初次insert也在该锁内。相同UID/game/requestId且payload jsonb相等重放同result，payload不等报幂等冲突；receipt与进度同事务。冲突result可落receipt，解决必须新requestId。receipt不自动过期删除，避免离线重放误执行。返回历史ack后不可覆盖更新的云版本或后续本地意图，必要时重新get读取。

普通编辑一座一批；有差异的迁移/替换/恢复用136项单批CAS（含未改变值与缺行revision0），保证预览完整集合同时有效，隐藏DLC也参与。整份目标完全无变化时显示无需迁移、禁止提交，不发空写入或同值批次。批次中同值也推进revision，保证统一收据。服务器拒绝重复ID、非法游戏/神庙/JSON形状/大小/revision值，不接受user_id参数。

## IndexedDB、持久队列与多标签页

账号envelope键包含projectRef/uid/game；缓存、loaded标记、outbox、conflicts、backups单readwrite事务更新。队列job保存schemaVersion/UID/game/requestId/immutable mutations/createdAt/source/attemptCount。commit成功才表示本机保存；失败保留会话意图并标unsaved，允许导出，暂停该操作云发送。损坏数据保留raw供恢复，不静默清空后标成功。

普通编辑overlay表示本地最终意图。未发送job可压缩，同座in-flight payload/requestId不可修改；后续操作待前序ack拿到新revision后再发。快速true→false不能因旧ack删除后续false。响应丢失保留原job重放receipt。冲突只阻断同座后续job，其它神庙可继续。

sender固定UID+authEpoch，job.uid必须与当前session用户一致。退出/切UID立即停sender、清在途视图引用并增加epoch；旧响应即使服务器已提交，也只能按原UID回写缓存，不能影响新UID画面。abort不代表服务器未写，重新登录靠相同receipt恢复。读云时先恢复该UIDenvelope、保留本地overlay；不清outbox。401/刷新失败暂停直到同UID重登。

IndexedDB内原子租约owner+expiry防跨tab并发推进；Web Locks可选优化而非唯一正确性依据。BroadcastChannel只通知其它tab重新读取；不以广播payload替代持久数据。focus/visibility/online/手动重试/登录触发读回与调度，无BroadcastChannel也能恢复。租约过期允许接管，CAS+receipt兜底。navigator.onLine仅作提示，实际fetch失败必须保留队列；429/暂时失败退避，协议/权限/认证错误不热循环。

## 冲突、迁移与备份恢复

冲突显示同座localCompleted、remote与revision；不能用completedIds并集作为日常合并。选cloud清除/备份该座待传意图，采用最新云值，保留其它座队列。选local重新取当前revision、新requestId CAS；再变化则再次提示。不强制upsert。

当前UID已真实加载且guest有进度时提供迁移预览，可稍后；设置入口可再次开。previewTransfer要求无pending/conflicts且可读取真实云端，离线不得凭未确认缓存首次预览。预览绑定UID+epoch、source原始数据、136行revision与数据版本；identity/source/云version变化即重做。apply前同步器加互斥屏障并重查pending/conflicts，期间账号编辑暂停。

merge只在用户确认后做一次完成并集；replace完整表达136座true/false，预览显示source/cloud/overlap、结果总数、新增/取消ID数。确认前同事务保存TransferBackup与整个immutable batch；备份含sourceRaw、sourceIDs、当前accountIDs、UID/project/game/dataVersion/时间。失败不开始迁移，guest原key原文始终不改；备份+job落盘后离线/中断保持完整批次，重试原payload，CAS冲突整批零写，不能重新盲并集。preview取消无job、无云写、无迁移标记。迁移成功标记只按UID/project/game保存，不代表可删除guest。

设置中列出backups，允许导出和previewRestore；恢复目标必须当前相同UID，恢复仍先备份、136项CAS。账号JSON导入复用TransferSource/preview/apply，原validateBackup校验先完成；访客JSON导入保持旧备份/替换流程。跨origin仍须JSON文件迁移。

## 真实保存状态

优先级：unsaved → conflict → error → syncing → offlineQueued → cloudSynced/localSaved。identity与saveState分开。

- localSaved：guest saveVerified成功；或账号缓存/outbox事务成功，等待发送。
- syncing：当前UID真实RPC在途；不能凭登录事件显示。
- cloudSynced：当前UID加载成功、所有目标获服务器确认、pending/conflicts为空且缓存commit成功。仅有缓存/无网络、仅Auth成功不够。
- offlineQueued：已持久化队列，真实网络失败或离线。
- error：schema/权限/认证/协议失败；有明确重试或登录入口。
- conflict：真实CAS mismatch，保留本机/远端预览。
- unsaved：本机事务失败，不能显示已保存；UI留当前会话值，可导出/重试。
